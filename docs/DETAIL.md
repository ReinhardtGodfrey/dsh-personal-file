# 个人档案：实现细节

一个在 DSH 后台运行的插件。它自己读 DSH 的会话日志，挑出档案对象说过、值得长期记住的话，按类别分档写进个人档案和记忆库。对话里的模型不会因为这件事被额外打扰，也不会临时起意乱写。

## 它读什么

- 只读 `$DSH_HOME/sessions` 下的 `session.v4.jsonl.zstd`，逐帧解压，只取 `user/message` 事件。
- 只认本人通道：`source.kind = user`（本机直接对话）；`qq` 通道按 `qq-bridge-config.json` 及其 `.bak-*` 备份里的绑定号码判定，只有号码等于配置项 `ownQq` 才算本人，留空则 QQ 消息全不算。群消息从正文前缀 `昵称（QQ号）：` 取号码。
- 时间注入、系统提醒、技能目录、子代理转述、工具结果一律跳过。
- 日常只看安装插件之后新产生的消息。装好那一刻会记下所有文件长度作为基线；装好前的历史由一次性「历史补扫」处理，处理完不再重复读。
- 富余的上下文只用于指代消解：同一会话里，窗口之前最近几条本人消息会附在提示词里，但不从里面提取事实。

## 它怎么判断

每次运行把新增消息按会话切块（单会话超过 40 条或 1.8 万字才切，批间带 3 条只读上下文），交给独立的一次模型调用。该调用只看这批原话、档案现状、记忆库现状、待确认清单，输出一份 JSON 操作清单。

分档按类别定，不靠单一分数：

- identity（5 分）：稳定身份、长期关系（家人、对象、亲密朋友）、长期工作方式、反复确认的偏好
- detail（4 分）：长期有用的具体事实或偏好，如项目细节、设备参数、具体流程
- minor（3 分）：次要但可留的信息
- temp（2 分）：临时状态、一次性安排、情绪，不写

档案只收 identity；记忆库收 detail 与 minor；更低档只进日志。规则类内容（插件用法、工具流程、路径、记账规则）即使长期有效也按 detail 或 minor 进记忆库，不进档案。模型输出 `kind`，插件按 `KIND_WEIGHTS` 换算成权重，权重只用于排序与替换。

「别做某事」的要求走单独一档，不进档案也不进记忆库：模型输出 `target: "ban"` 的 add，插件校验原话、按 `banWeight` 分 5（绝对禁区）、4（必须先问）、3（尽量避开）三档，先过相似度自审，再落 `data/禁令待审.md`，等人工在设置页审批。

落在边界上的「新增」会再问一次模型，两次按类别取较低档：5+4 判 4，5+2 直接丢。

拿不准真假或拿不准是否属于本人的，模型输出 `uncertain: true` 的 add，进 `data/待确认.md`，不占档案也不占记忆库；后续消息证实后再按正常流程写入，写入时自动把该条从待确认里摘掉。

## 记忆库的结构

- 按主题分节：`## 主题：<2–10 字>`，同一件事永远进同一节，不另起新节。
- 每条前面由插件补日期：`- YYYY-MM-DD：内容`；模型给的 `line` 不自己写日期。`replace` 保留旧行的日期。
- 不设总量上限。半年没再被提到、且此后没有相似条目的 minor(3) 条目会被自动清理；清理前整库备份，日志单列「自动清理」段。
- `data/memory-index.json` 记录每条写入日期、主题、类别、原句与来源会话、时间，正文一个字不动。
- 记忆库只存盘，不注入任何对话，也没有给模型读它的工具。

## 写入前会被拦下的情况

- 依据的原话片段不在本批消息里逐字出现
- `old` 在目标文件里找不到，或不止一处
- 这条内容已经存在（去掉日期前缀后相似度 ≥0.9 视为重复，不重复写）
- 新主题节的 topic 为空或超过 20 字
- 单条超过 200 字、每批每文件新增/修改超过 12 条、删除超过 3 条
- 改完档案会超过 60000 字节
- 档案或记忆库在本轮开始后被外部改过（按哈希比对，宁可这轮不写）
- 任一批次模型调用或解析失败（整轮不写，下次从头重跑这批消息）

## 写入与留底

- 默认干跑：只有 `data/mode.txt` 内容为 `live` 才真正写文件。干跑会把「本来会写什么」记进日志。
- 真写时先把档案和记忆库复制到 `backups/<时间戳>/`，再原子替换；备份默认保留最近 60 份。
- 每轮运行追加到 `logs/YYYY-MM-DD.md`：状态、处理了多少会话/消息、每条新增的依据原话与会话、每条修改的旧行和新行、每条删除的旧行、自动清理了哪些、待确认新增了哪些、被拒绝的原因、错误、备份路径。
- `logs/最新变更.md` 是给外部工具读的摘要，每次运行覆盖；同时另存一份到 `logs/变更历史/<日期>-<时分秒>.md`，不自动清理。
- 状态在 `data/state.json`：安装时刻、上次运行、每个文件的读取位置和 seq 水位、最近几条上下文、档案与记忆库的哈希。中断后按文件读取位置续读，不会扩大范围。
- `data/last-run.json` 是最近一轮的完整结果快照。

## 禁令的审核链路

1. 模型只输出 `target: "ban"`、`banWeight`、`line`、`quote`，不直接写文件。
2. `lib/bans.js` 的 `queueBans` 先自审：和规则文件（`rulesPath`）相似度 ≥0.6、和记忆库 ≥0.8、或待审清单里已有同一条，都不进清单，原因与相似度写进日志「禁令自审」段。
3. 通过自审的落 `data/禁令待审.md`，格式 `- [档位] 内容 ｜依据：原话 ｜会话 ｜时间`。
4. 设置页「禁令待审」页签按条列出来，点通过调 `POST /dsh-profile-keeper/bans`：先备份规则文件到插件 `backups/<时间戳>/`，再把条目追加到规则文件的「明确禁令」节（渲染成 `- [档位] YYYY-MM-DD：正文`），并从待审清单删掉；驳回只删清单。
5. 未审批的禁令不会被当成规则执行，也不会进档案。

## 设置页接口

- 面板注册在客户端插件的 `settings.section`；宿主侧两个路由都用 `ctx.effect` 包 `webServer.register`，只开在 DSH 本地 webServer 上。
- `GET /dsh-profile-keeper/overview`：读档汇总，返回档案分节、记忆库按主题的分组与日期、各权重条数、待确认条数、禁令条数、上次运行结果。不写盘。
- `POST /dsh-profile-keeper/bans`：body 为 `{ "approve": ["<正文>"], "reject": ["<正文>"] }`，至少一项，否则 400；返回通过/驳回条数与备份路径。
- 客户端模块改动后需要重启 DSH 才会加载新的一代 JS。

- DSH 一启动就补跑一次。
- 之后每分钟检查一次本地时间：过了 `runHour`（默认 13 点）且当天还没跑过，就跑一次。
- 失败后 5 分钟内不重试；失败的轮次不推进读取位置和上次成功时间。
- `data/disabled` 存在时完全跳过。

## 开关

- 配置走插件 patch 里的 `config`，可用字段：`archivePath`、`rulesPath`、`memoryPath`、`dshHome`、`sessionsRoot`、`ownQq`、`runHour`、`keepBackups`、`maxTokens`、`llm.provider`、`llm.model`、`llm.reasoningEffort`。
- 改模型只影响这个插件自己的判断调用，不影响会话里用的模型。留空即用宿主默认模型。

## 已知边界

- 只处理能逐字核对的明文消息；图片、语音、文件内容不在提取范围。
- QQ 消息本身不带发言人字段，身份靠 `qq-bridge-config.json` 的绑定号码判定；绑定文件里找不到的会话、以及群消息前缀缺 QQ 号的，都会被跳过。
- 指代消解只回溯同会话最近几条消息；更早的老话题可能理解不准。
- DSH 不常驻，插件只在 DSH 运行期间工作；停机期间到点的批处理由下次启动的补跑补上。
